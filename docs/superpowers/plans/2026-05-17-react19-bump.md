## Task 4: Fix the `JSX` global namespace removal (TS2503/TS2304)

**Background:** `@types/react` 19 removed the global `JSX` namespace. `JSX.Element` now must be sourced from `React`. Two acceptable replacements:

- `React.JSX.Element` — requires a `React` import, but most files in this repo already have one for hooks.
- Just remove the annotation — TS infers the function's return type from the JSX body anyway.

**Decision for this plan:** Remove the annotation. Reasoning: (a) `: JSX.Element` was decorative — TS already inferred it — and removing it is a smaller, cleaner diff than threading `React.JSX` everywhere; (b) it eliminates the dependency on the host's JSX namespace shape entirely, surviving future `@types/react` changes; (c) it matches the "compat-only, no churn" scope of this PR. If a specific file _needs_ an explicit return type (e.g., it's exported as a typed factory), use `React.JSX.Element` for just that file.

**Files:**

- Modify: every `*.ts`/`*.tsx` under `apps/web/src` with a `JSX.Element` annotation (~115 sites, ~30 files based on the audit).

- [ ] **Step 1: List affected files**

```bash
grep -rEln "JSX\.Element|JSX\.IntrinsicElements" apps/web/src --include="*.ts" --include="*.tsx" > /tmp/jsx-files.txt
wc -l /tmp/jsx-files.txt
```

Expected: ~30 files.

- [ ] **Step 2: Apply mechanical removal of `: JSX.Element` return annotations**

Run this on each file in `/tmp/jsx-files.txt`. The pattern is `): JSX.Element {` → `) {` for function declarations, and `=> JSX.Element` → arrow type removed in the same way.

Use `sed` to apply the two safe substitutions (works on macOS BSD sed):

```bash
while IFS= read -r f; do
  sed -i '' -E 's/\): JSX\.Element \{/) {/g' "$f"
  sed -i '' -E 's/\): JSX\.Element$/)/g' "$f"
done < /tmp/jsx-files.txt
```

This only removes the return annotation when it is `: JSX.Element` followed by `{` or end-of-line. It does **not** touch `JSX.Element` inside generic params, type aliases, or `JSX.IntrinsicElements` — those need manual handling.

- [ ] **Step 3: Handle remaining `JSX.Element` references manually**

```bash
grep -rEn "JSX\.Element|JSX\.IntrinsicElements" apps/web/src --include="*.ts" --include="*.tsx"
```

For each remaining hit:

- `JSX.Element` inside a type alias / interface / generic: replace with `React.JSX.Element`, ensuring `import { type JSX } from 'react'` or `import React from 'react'` exists at the top.
- `JSX.IntrinsicElements['div']` etc.: replace with `React.JSX.IntrinsicElements['div']`.
- `JSX.Element[]`: replace with `React.JSX.Element[]`.

If you find zero remaining hits, skip ahead.

- [ ] **Step 4: Re-run the build, expect a smaller error set**

```bash
pnpm --filter @prayer/web build 2>&1 | tee /tmp/react19-tsc.log
grep -E "error TS" /tmp/react19-tsc.log | sed -E 's/.*error TS([0-9]+).*/TS\1/' | sort | uniq -c | sort -rn

- [ ] **Step 5: Commit**

## Task 5: Fix residual type errors

**Files:**

- Modify: whichever `apps/web/src` files surface remaining TS errors.

This task is intentionally not pre-baked because the residual error set depends on what `@types/react` 19 tightens in your exact component shapes. The diagnostic recipe is the deliverable.

grep -E "error TS" /tmp/react19-tsc.log | sed -E 's/.*error TS([0-9]+).*/TS\1/' | sort | uniq -c | sort -rn
```

- [ ] **Step 2: Fix in batches, one error code at a time**

Common React-19-specific fixes:

**`Property 'children' is missing in type ...` on a component that takes children:**
Add `children?: ReactNode` (or `children: ReactNode` if always required) to the component's props interface. `@types/react` 19 removed the implicit `children` from `FC` / `FunctionComponent`.

**`Type '... | undefined' is not assignable to type 'ReactNode'`:**
React 19's `ReactNode` no longer includes `void` / certain narrow forms. Add an explicit return:

```tsx
{
  condition ? <Thing /> : null;
} // not `condition && <Thing />` when condition can be `0`
```

**`useRef<T>(...)` errors:** Not expected — the audit found zero zero-arg `useRef` calls — but if one appears, supply an initial value: `useRef<HTMLDivElement | null>(null)`.

**`forwardRef` deprecation warnings:** None expected in this repo. Ignore — deprecation is not removal in 19.x.

For any error that doesn't fit these recipes: capture the exact message, the file, and the surrounding 10 lines in a new comment block in this plan file, then ask for review before fixing speculatively.

Likely React-19-only failure modes:

- **Act warnings → hard errors:** React 19 promotes some `act()`-not-wrapped warnings to test failures. Fix by wrapping the offending state update in `act()` from `@testing-library/react`.

For each failure, fix the test (not the production code) unless the failure points at a legitimate React 19 behavior change you want to preserve.
